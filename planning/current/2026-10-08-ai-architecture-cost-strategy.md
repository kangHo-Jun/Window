# 창호 웹사이트 AI 구성과 비용 통제 전략

> 2026-10-12 범위 정정: 아래는 분리 전 초안/기록이다. 챗봇·AI 관련 내용은 모두 2차 B2C에 속하며 개발 중단 상태다. B2B 우선·B2C 확장 가정과 이전 다음 작업 지시 대신 [2차 재개 계획](B2C_MASTER_PLAN.md)과 [전체 구분](MASTER_PLAN.md)을 따른다. 1차 B2B 요구사항은 별도 설명 대기다.

작성일: 2026-10-08
상태: 개발 준비 기획. 코드·인프라 변경이나 배포 완료를 뜻하지 않는다.

## 목적과 적용 범위

공개 웹사이트에서 고객의 창호 문제를 이해하고 선택 기준·현장 확인 계획·필요시 가견적·담당자 상담으로 연결한다. AI 사용량을 제한하면서 기본 안내와 접수는 계속 제공한다. 독립적인 대화형 홈페이지 또는 기존 홈페이지 임베드 여부는 추후 결정하며, 화면과 상담 API를 분리한다. 초기 B2B와 후속 B2C라는 최신 사업 기획을 바꾸지 않는다.

## 초기 구성안

웹 화면 → 기존 상담 서버 → 규칙 기반 처리 또는 지식 검색과 AI → 설명·카드·선택지 반환.

프로젝트 기록에 있는 Next.js/Cloud Run과 Firestore를 재사용하는 것을 우선한다. 기존 사용 모델의 유지 여부는 품질·실측 비용을 보고 결정하며 이 문서로 모델을 재확정하지 않는다. 운영 기록에 남은 /api/chat HTTP 429 원인은 구현 전 별도 확인한다.

| 구성 | 책임 |
|---|---|
| 웹 화면 | 대화, 선택지, 제품·사례 카드, 상담 내용 확인·제출 |
| 상담 서버 | 비밀키 보관, 요청 검증, 사용량 제한, AI 호출, 데이터 조회·접수 |
| Firestore 등 공유 저장소 | 상담 상태, 중복 요청 방지, 여러 서버가 공유하는 사용량·예산 기록 |
| 구글 시트 | 초기 제품·FAQ 관리표, 상담 접수와 담당자 처리 현황 |
| 검색용 지식 저장소 | 승인 자료의 관련 부분 검색, 출처·적용 조건 제공 |
| AI | 자유문 이해, 근거에 따른 설명, 추가 질문, 상담 요약 |

구글 시트는 임시 데이터 관리 도구이며 서버 자체가 아니다. Apps Script를 붙이면 소규모 시험용 서버 역할은 가능하지만, 공개 챗봇을 위해 기존 서버를 시트/GAS로 대체하지 않는다.

## AI를 호출하는 기준

지역·주거 형태·공간 선택, 고정 FAQ, 제품 목록, 계산, 연락처 입력·접수는 프로그램과 데이터로 처리한다. 자유로운 상황 설명 해석과 개인화된 설명에 AI를 사용한다. 명확한 버튼 요청은 AI 분류를 거치지 않는다. 자유문 분류가 필요하면 가능할 때 답변 생성과 한 번에 처리한다.

RAG는 관련 자료만 검색해 AI에 전달하는 방식으로 구성한다. 초기에는 모델 별도 학습을 하지 않는다. 제품 사양·가격표·계산식은 구조화된 데이터에서 가져오고 AI가 금액·보증·성능 수치를 생성하지 않게 한다. 근거가 없으면 미확인 사항을 알리고 현장 확인 또는 담당자로 연결한다.

대화 상태는 주거 형태, 불편, 교체 범위, 확정/미정 사양, 희망 시기 등을 별도로 저장한다. AI 출력은 설명, 추가 질문, 카드, 출처, 상태 변경 제안으로 구분하고 서버가 형식을 검증한다. AI의 상태 변경 제안을 그대로 신뢰하지 않는다. 상담 신청은 고객 확인과 동의 후 서버가 접수한다.

## 비용 통제 정책 초안

아래 숫자는 초기 제안이며 확정 운영값이 아니다.

| 항목 | 제안 |
|---|---|
| 비회원 세션 | AI 답변 10회부터 시험, 초과 시 일반 안내·상담 신청 제공 |
| 요청 속도 | 세션별 동시 요청 1개, 세션/IP별 짧은 시간 반복 요청 제한 |
| 입력 | 1,000자 내외, 서버에서 별도 토큰 한도 검사 |
| 출력 | 짧은 설명 중심, 모델의 출력·추론 한도를 포함한 호출별 상한 |
| 문맥 | 최근 대화와 구조화된 상태만 전달, 전체 기록 반복 전송 금지 |
| 자료 | 관련 자료 일부만 검색, 공통 정보는 버전별 캐시 |
| 모델 | 검증된 저비용 모델 기본, 상위 모델 전환은 제한된 조건에서만 |
| 추가 호출 | 검색·요약·재시도·도구 반복 횟수에도 상한 설정 |
| 자동 요청 | 세션/IP 통제와 의심 요청 추가 인증 조합 |
| 전체 비용 | 일·월 예산 검사, 호출 전 예약 및 완료 후 실제 비용 정산 |

새 세션 발급만으로 제한이 풀리지 않도록 여러 신호를 조합한다. 공유 IP의 정상 고객도 고려한다. 질문 주제 제한 프롬프트만으로 비용을 방어하지 않는다. 요청 검사와 예산 확인은 AI 호출 전에 실행한다.

예산 예약은 공유 저장소의 원자적 갱신으로 처리한다. 여러 서버가 동시에 호출해도 예약 합계가 한도를 넘지 않게 한다. 요청 ID로 중복 실행을 막고 실패·타임아웃 시 무조건 예약을 반환하지 않는다. 과금 여부가 불명확한 요청은 기록·대조 후 정산한다. 예산 저장소 장애 시 신규 AI 호출을 멈추고 기본 안내로 전환한다.

공통 답변 캐시는 승인된 비개인 정보에만 적용한다. 가격·보증 변경 시 캐시를 갱신한다. 개인 상담 결과는 다른 고객에게 재사용하지 않는다. 요약 생성 자체의 비용도 사용량에 포함한다.

월 AI 비용은 이용 세션 수 × 세션당 호출 수 × 평균 호출 비용으로 추정하고 검색·임베딩·추론 등 부가 비용을 포함한다. 서버·DB 비용은 별도로 집계한다. 예산 알림만으로 호출이 차단된다고 가정하지 않는다. 상한은 이 엔진을 통과하는 호출에 적용되므로 API 키 접근을 제한하고 별도 도구 사용 비용도 확인한다.

## 구글 시트 운영 범위

제품·FAQ 관리표와 고객 접수표를 분리한다. 제품·FAQ는 ID, 내용, 출처, 적용 조건, 갱신일, 승인 상태를 기록한다. 고객 정보는 승인된 담당자와 서버만 접근한다. API 키·비밀정보는 시트나 브라우저에 저장하지 않는다.

자료는 서버가 캐시하거나 검색용 저장소로 반영하며 메시지마다 시트 전체를 읽지 않는다. 기존 CSV와 시트에 가격 원본을 이중 운영하지 않는다. 시트로 가격 관리까지 옮길지는 별도 결정하고 단일 원본과 검증 절차를 정한다.

상담은 고객 제출 후 요청 ID를 기준으로 한 건만 기록한다. 대화마다 append하지 않는다. 시트 쓰기 실패는 재시도 대상으로 보존하고, 서버가 실제로 접수를 보관한 경우에만 접수 완료를 안내한다. 사용량·예산의 실시간 원장은 시트에 두지 않는다.

Google Sheets API는 기본적으로 읽기·쓰기 각각 프로젝트당 분당 300회, 사용자당 프로젝트별 분당 60회 한도를 안내한다. Apps Script도 실행 시간과 동시 실행 제한이 있다. 따라서 위 역할 분리를 적용한다.

출처: [Sheets API 사용 한도](https://developers.google.com/workspace/sheets/api/limits), [Apps Script 할당량](https://developers.google.com/apps-script/guides/services/quotas). 확인일 2026-10-08. 실제 계정별 한도는 구현 시 확인한다.

## 구현 순서와 완료 기준

1. 승인된 제품·FAQ와 대표 상담 질문을 정리한다.
2. 규칙 기반 기본 상담과 AI 응답 경계를 확정한다.
3. 서버의 요청 제한·공유 사용량 기록·예산 예약/차단을 구현한다.
4. 지식 검색과 짧은 답변, 누적 상담 상태를 연결한다.
5. 상담 요약·고객 확인·중복 없는 시트 접수를 연결한다.
6. 실제 상담 예시로 품질과 세션당 평균·상위 비용을 측정한다.

검증 항목: 근거 없는 가격/보증 차단, 동시 호출 시 예산 초과 방지, 제한 후 일반 안내 유지, 반복 제출 중복 방지, 다른 고객 정보 미노출, 검색/AI/시트 장애 처리. 사진·음성·자동 견적 확대는 기본 흐름 검증 후 결정한다.

남은 결정: 일·월 예산, 사용할 모델과 출력 한도, 비회원 제한값, 시트 항목·접근자·보관 기간. 지금은 문서 기록 단계이며 코드 수정과 배포는 별도 작업이다.
