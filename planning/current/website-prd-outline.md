# 대산 창호 웹사이트 PRD 큰 줄기

> 2026-10-12 범위 정정: 아래는 분리 전 초안/기록이다. 챗봇·AI 관련 내용은 모두 2차 B2C에 속하며 개발 중단 상태다. B2B 우선·B2C 확장 가정과 이전 다음 작업 지시 대신 [2차 재개 계획](B2C_MASTER_PLAN.md)과 [전체 구분](MASTER_PLAN.md)을 따른다. 1차 B2B 요구사항은 별도 설명 대기다.

작성일: 2026-10-08 · 상태: 기획 초안

고객이 자신의 창호 문제와 해결 방향을 이해하고 대산의 상담·현장 확인 역량을 신뢰하도록 돕는 창호 웹사이트를 구축한다. 챗봇은 짧은 선택과 대화로 현장에 맞는 판단 기준과 확인 계획을 제공하는 핵심 홍보·상담 수단이다. 필요한 고객에게 예상 비용을 안내하고 담당자 상담과 실측으로 연결한다. 초기 B2B, 이후 B2C 확장 방향은 유지한다.

## 1. 제품의 목적

고객은 사이트에서 대산이 어떤 업체인지, 무엇을 공급하는지, 대략 얼마가 필요한지, LX 완성창을 선택할 이유가 무엇인지 이해할 수 있어야 한다. 대산은 고객이 제공한 자료와 관심사를 바탕으로 상담하고, 구매 의사를 확인한 뒤 실측을 진행한다. 정확한 견적은 실측 후 제공한다.

첫 단계의 직접 목표는 고객이 자신의 상황에서 무엇을 선택·확인해야 하는지 이해하고 “대산이라면 내 상황을 제대로 확인하고 진행해 주겠다”는 신뢰를 갖는 것이다. 가견적은 예산 판단을 돕는 경로이며, 이를 생략하고 유효 상담으로 연결되어도 성공이다. 유효 상담과 실제 실측은 후속 사업 성과로 확인한다. 온라인 주문·결제 완료는 초기 핵심 목표에 포함하지 않는다.

금액은 현실적인 예산 판단이 가능한 수준이어야 하며 임의로 생성하지 않는다. 다만 제품 기획의 중심은 정밀 산출 범위 확대보다 가견적에 도달하기 전 전문성과 신뢰를 체감하는 경험이다. 기존 가격 오류는 이 경험을 훼손하지 않도록 고칠 기본 품질 과제다.

## 2. 고객과 운영 단계

| 구분 | 대상과 목적 | 제공할 서비스 |
|---|---|---|
| 1단계 | B2B 고객의 제품 검토와 견적 상담 | 대산·상품 소개, 비교 가견적, LX 완성창 가치 설명, 실측 상담 연결 |
| 2단계 | B2C 고객의 요구 파악과 선택 지원 | 생활 속 불편과 요구를 파악하는 전문가 챗봇, 설명과 조건별 상담 확대 |

B2B 세부 업종과 사이트를 직접 사용하는 사람이 업체 담당자인지 최종 소비자인지는 후속 확인한다. 초기 콘텐츠는 고객에게 보여줘도 이해할 수 있는 쉬운 표현을 기본으로 한다.

## 3. 사이트에 들어갈 내용

다음은 콘텐츠 묶음이며, 각각을 독립 페이지로 만들지는 UI 설계 단계에서 정한다.

| 콘텐츠 | 고객이 얻어야 할 답 | 준비할 자료 |
|---|---|---|
| 대산 소개 | 어떤 업체이며 상담과 실측을 맡길 수 있는가 | 실제 사업·서비스 정보, 담당 범위, 연락 방법 |
| LX 완성창 소개 | 어떤 상품을 취급하며 나에게 어떤 의미가 있는가 | 취급 제품, 제작·공급 방식, 확인된 특징 |
| 선택 기준과 가격 차이 | 다른 선택과 무엇이 다르고 추가 비용의 이유는 무엇인가 | 비교 조건, 제품별 근거, 보증·서비스 적용 범위 |
| 시공·공급 사례 | 비슷한 조건에서 어떤 결과가 있었는가 | 공개 가능한 실제 사진·조건·사례. 자료 확보 후 반영 |
| 문제 해결 상담·가견적 | 내 현장에서 무엇을 선택·확인해야 하고 예산은 어느 정도인가 | 답변별 설명, 실제 확인 절차, 제품 근거, 계산 기준 |
| 상담·실측 안내 | 다음에 무엇을 하면 되며 정확한 견적은 언제 받는가 | 자료 상담→구매 의사 확인→실측→정식 견적 절차 |
| 자주 묻는 질문 | 가격·사양·시공·사후 대응에 관한 기본 의문 | 대산이 확인한 답변과 상담 필요 조건 |

## 4. 고객의 기본 흐름

사이트 방문 → 문제·제품·예산 등 목적 선택 → 필요한 질문과 상황별 설명 → 현장에 맞는 선택 기준·확인 계획 → 필요시 가견적 → 상담 신청 → 담당자 상담과 구매 의사 확인 → 실측 → 정식 견적.

고객은 콘텐츠를 모두 읽지 않고도 가견적이나 상담으로 바로 진입할 수 있다. 상담을 먼저 원하는 고객에게는 가견적 완료를 강제하지 않는다.

## 5. 첫 구현의 원칙

- UI는 익숙한 기본 구성으로 만든다. 선택에 따라 설명이 달라지고, 짧게 참여할 때마다 유용한 결과를 받는 상호작용은 1차 핵심 요구다. 콘텐츠의 정확성, 읽기 쉬움, 모바일 입력 편의, 수정 가능성을 확보한다.
- 별도의 고급 시각 디자인, 복잡한 애니메이션, 브랜드 연출은 후속 작업으로 둔다.
- 대산의 LX 완성창을 중심으로 설명하되, 비교 가격과 장점은 확인된 자료로 제시한다.
- 실측 전 예상금액과 실측 후 정식 견적을 명확히 구분한다.
- 실제 자료가 없는 실적·후기·품질 수치·보증 내용은 만들어 넣지 않는다.
- 상담 신청이 실제 접수되고 담당자가 이전 대화와 견적 조건을 확인할 수 있어야 한다.

## 6. 지금 진행할 상세 PRD

현재 작업 대상은 사이트에 포함될 **문제 해결 상담과 가견적 체계**다. 상세 범위는 `chatbot-estimate-prd.md`, 현재 구현과의 대조 및 대표 대화는 `chatbot-problem-solving-plan.md`에서 관리한다. 프로젝트 내 개선안 파일명은 `2026-10-08-problem-solving-chatbot-plan.md`다.

1. 고객이 전문성·관련성·신뢰를 체감할 장면과 이를 만드는 질문·응답 순서
2. 모르는 정보·자료 제출·답변 수정 처리
3. 가격 산출 기준과 지원 가능한 범위
4. LX·KCC·기타 창호의 비교 조건과 차액 표시
5. LX 완성창의 장점을 설명하는 기준
6. 실측 상담 신청과 담당자 인계
7. 데이터 준비 및 완료 판정 기준

웹사이트의 모든 페이지를 상세 설계하거나 B2C 전문가 상담 전체를 한 번에 구현하지 않는다. 먼저 챗봇 가견적의 한 흐름을 실제로 작동하게 만든다.

## 7. 성과 확인

대표 고객이 자기 현장의 선택 기준과 확인할 사항을 설명할 수 있는지, 대산을 신뢰하거나 상담을 원하게 된 구체적 근거가 있는지 먼저 확인한다. 목적별 유용한 안내 도달, 상담 신청, 유효 상담, 실제 실측과 이탈 이유를 기록한다. 가견적 도달은 선택 경로의 지표이며 단독 성공 기준으로 삼지 않는다. 지원하지 못한 견적 조건, 담당자의 재질문 횟수, 가견적과 정식 견적 차이의 원인도 함께 기록한다. 목표 수치는 초기 운영 자료를 바탕으로 정한다.

## 8. 확정할 사업 조건

B2B 우선 업종과 직접 이용자, 서비스 지역 및 공급·시공 범위, 비교 가격의 원본, LX 완성창의 입증 가능한 장점, 상담 접수 채널과 담당자 처리 방식을 확정해야 한다. 미정 사항은 상세 PRD에서 추적하며 임의로 영업 조건을 정하지 않는다.
