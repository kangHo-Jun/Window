# 대산 문제 해결 상담·가견적 체계 상세 PRD 초안

> 2026-10-12 범위 정정: 아래는 분리 전 초안/기록이다. 챗봇·AI 관련 내용은 모두 2차 B2C에 속하며 개발 중단 상태다. B2B 우선·B2C 확장 가정과 이전 다음 작업 지시 대신 [2차 재개 계획](B2C_MASTER_PLAN.md)과 [전체 구분](MASTER_PLAN.md)을 따른다. 1차 B2B 요구사항은 별도 설명 대기다.

작성일: 2026-10-08 · 상위 문서: `website-prd-outline.md` · 상태: 업무 체계 초안

챗봇은 고객이 자신의 창호 문제와 해결 방향을 이해하고, 대산이 무엇을 확인해 어떻게 상담을 이어갈지 납득하도록 돕는 홍보·상담 도구다. 현재 상세화할 대상은 목적 선택→필요한 질문과 설명→현장별 선택 기준·확인 계획→필요시 가견적→담당자 상담의 경험이다. 가견적 없이 상담으로 연결되는 것도 정상 경로다. 가격표, 지원 사양, 제품별 장점 및 실제 운영 절차는 이를 뒷받침한다.

기존 구현 대조·대표 대화·화면 역할·개발 순서·완료 판정은 `chatbot-problem-solving-plan.md`에 구체화했다. 프로젝트 내 파일명은 `2026-10-08-problem-solving-chatbot-plan.md`다. 아래 가격·인계 품질 요구는 유지하되 대화 순서는 최신 개선안을 따른다.

## 1. 확정 방향과 초안의 경계

사용자가 확정한 방향은 B2B 우선, 실측 전 대략적인 금액 제공, LX·KCC·기타 창호의 가격 차이 설명, LX 완성창 중심의 가치 전달, 실측 후 정확한 견적 제공이다. UI는 기본적인 수준으로 구성하고 내용을 우선한다.

이하 입력 항목, 처리 규칙, 데이터 구조, 검증 기준은 이 방향을 실행하기 위한 설계 초안이다. 구체 가격·마진·오차율·보증 조건과 B2B 세부 업종은 이 문서로 확정하지 않는다.

## 1.1 첫 버전의 핵심 경험

- 고객이 정보를 주면 봇은 입력을 되풀이하는 데서 그치지 않고 그 정보가 선택에 어떤 의미인지 짧게 설명한다.
- 고객이 놓치기 쉬운 판단 기준을 상황에 맞춰 알려준다. 기술 용어의 양보다 고객이 얻는 판단의 유용성을 우선한다.
- 공개 가능한 실제 사례가 있으면 유사한 조건과 다른 조건을 함께 설명한다. 아직 검증되지 않은 사례 추천 기능은 제안으로 관리한다.
- 질문 사이에 필요한 설명·조건 변화·비교를 배치한다. 모든 질문 뒤에 긴 설명을 붙이거나 가견적 앞에 콘텐츠 열람을 강제하지 않는다.
- LX 완성창의 장점은 고객의 관심과 연결하고 근거를 갖춘 내용으로 설명한다.
- 가견적은 누적된 이해와 신뢰를 다음 상담으로 잇는 결과다. 금액의 현실성과 일관성은 유지하되, 정밀 견적 시스템 전체를 첫 버전 목표로 확대하지 않는다.

킬러 경험의 설계 가설은 “고객의 답에 따라 달라지는 선택 기준과 현장 확인 계획”이다. 고객 진술·가능한 설명·검증된 근거·미정 사항을 구분한다. 원인이나 설치 효과를 온라인에서 확정하지 않으면서도 고객에게 구체적인 판단과 다음 행동을 제공한다. 어떤 장면이 실제로 신뢰를 만드는지는 대산의 상담 사례와 대표 고객 반응으로 검증한다.

## 2. 핵심 고객 과제

- 내 상황을 이해하는 업체인지, 상담을 맡길 만한지 판단한다.
- 놓치고 있던 선택 기준을 알고 내가 중요하게 볼 항목을 정리한다.
- 내 현장의 창호에 대략 어느 정도 예산이 필요한지 파악한다.
- 같은 요구를 기준으로 LX와 다른 선택의 가격 차이를 이해한다.
- 추가 비용을 내고 LX 완성창을 선택할 이유를 판단한다.
- 이미 전달한 내용을 반복 설명하지 않고 대산 담당자와 실측 상담을 이어간다.

## 3. 이번 범위

| 포함 | 후속 범위 |
|---|---|
| 선택지와 자유 입력을 이용한 조건 수집 | B2C의 모든 불편을 다루는 심층 진단 |
| 지원하는 사양·표준 구성의 가견적 산출 | 모든 비표준·특수 제작 사양의 자동 견적 |
| 비교 가능한 제품의 예상금액과 차액 | 온라인 주문·결제·제작 발주 |
| 확인된 자료를 이용한 제품 설명 | 검증되지 않은 절감액·성능 효과의 자동 예측 |
| 자료 첨부를 상담 정보로 전달 | 도면·사진만으로 치수와 가격을 자동 확정 |
| 상담 신청 저장과 담당자 인계 | 실측 일정 자동 확정, 복잡한 영업 관리 시스템 |

첨부 기능은 접수 채널과 보관 방식을 확정한 뒤 연결한다. 사진·도면 제출 자체가 자동 계산 완료를 의미하지 않는다.

## 4. 대화와 업무 흐름

| 단계 | 고객에게 제공할 내용 | 처리 결과 |
|---|---|---|
| 시작 | 불편·설치 걱정 / 제품·사양 검토 / 예산 확인 | 상담 목적, 바로 상담 선택 가능 |
| 필요한 질문 | 현재 판단을 바꾸는 현장 관찰이나 공급·시공 범위 | 알려진 사실·미정 사항을 구분 |
| 상황 해설 | 답변에 따라 달라지는 선택 기준과 확인 방법 | 고객이 얻는 첫 유용한 안내 |
| 상담 정리 | 현장 목표, 관찰 사실, 선택 기준, 확인할 사항 | 수정 가능한 누적 요약 |
| 근거 | 해당 제품 자료, 실제 업체 절차, 관련 실제 사례 | 적용 조건과 남은 불확실성 |
| 예산 선택 | 원하는 고객에게 창별 사양·수량·계산 가정 확인 | 비교 가능한 조건과 견적 버전 |
| 가견적 | 지원 범위의 예상금액, 차액, 포함·제외 범위 | 대화를 유지하는 예산 카드 |
| 상담 신청 | 전달할 상담 정리·예산·미정 사항과 연락 방법 확인 | 실제 접수 결과 |
| 담당자 처리 | 구매 의사와 미정 사항 확인, 실측 협의 | 실측 여부와 후속 정식 견적 |

위 흐름은 모든 고객에게 강제하는 설문이 아니다. 제품 사양을 아는 B2B 고객은 불편 인터뷰 없이 제품·예산 경로로 간다. 고객이 중간에 제품 질문을 하면 답변 후 보류한 상담 단계로 돌아온다. 이미 답한 항목은 다시 묻지 않는다. 모른다는 답변은 미정 상태로 보존하며, 나중에 입력하거나 수정할 수 있다. 질문·부정 표현을 증상 선택으로 오인하지 않는다. 결과를 봐도 대화가 종료되지 않는다.

## 5. 수집할 정보

| 정보 묶음 | 항목 | 수집 시점과 규칙 |
|---|---|---|
| 현장 | 지역, 건물 용도, 신축·교체, 공급만·시공 포함 | 지원 범위와 계산에 필요한 항목부터 질문 |
| 대상 창 | 설치 위치, 창 종류, 크기, 수량, 전체·일부 교체 | 창별로 저장. 전체 선택은 구체 창 목록으로 확인 |
| 치수 근거 | 고객 측정·도면·표준 구성·미정 | 제작 치수나 실측 완료로 취급하지 않음 |
| 계산 사양 | 모델, 단창·이중창, 유리, 색상 등 가격에 영향을 주는 조건 | 아는 항목만 입력. 기본 사양 사용 시 결과에 표시 |
| 고객 관심 | 예산, 성능, 외관, 사후 대응, 희망 시기 | 필요한 설명에 활용. 가격에 영향 없는 답변으로 금액을 변경하지 않음 |
| 현장 추가 조건 | 철거, 마감, 반입·양중, 배송 등 | 해당 비용을 계산할 때 추가 확인. 모르면 제외·미정으로 표시 |
| 참고 자료 | 도면, 사진, 기존 사양·견적 자료 | 담당자 검토 자료로 취급. 자동 추출은 별도 검증 후 도입 |
| 연락 | 업체·담당자, 연락 수단, 상담 요청 | 상담 신청 때 수집. 가견적 열람 전에 연락처를 강제하지 않음 |

상세 손잡이 규격, 개폐 방향, 비대칭 창 치수 등은 선택한 사양이나 가격 계산에 필요할 때만 묻는다. 기존 9단계 상담 초안 전체를 최초 필수 입력으로 옮기지 않는다.

## 6. 가견적 산출 체계

### 6.1 계산과 설명의 역할

금액은 승인된 가격 데이터와 하나의 계산 로직에서 산출한다. AI는 고객 표현을 입력 항목으로 정리하고 계산 결과를 설명한다. AI가 가격, 할인율, 비교 배율, 오차율을 임의로 만들지 않는다.

### 6.2 입력 수준에 따른 결과

| 입력 수준 | 허용할 결과 |
|---|---|
| 규격·수량·사양이 지원 가격표와 일치 | 해당 조건의 가견적과 미확정 비용 표시 |
| 고객 정보가 승인된 표준 구성과 일치 | 표준 구성의 창 목록·가정을 보여준 뒤 대표 예상금액 또는 근거 있는 범위 제공 |
| 주요 정보가 부족하거나 지원 구성과 불일치 | 필요한 추가 질문 또는 담당자 확인. 실제 요청의 가격처럼 임의 기본값을 표시하지 않음 |

평수만으로 자동 계산할 수 있는지는 표준 구성 자료의 적합성으로 결정한다. 지원하지 못하는 사례가 있을 수 있으나, 첫 출시에는 명시한 대표 조건에서 실제 비교 금액이 나와야 한다. 금액 없는 상담 접수만으로 핵심 기능 완료를 판정하지 않는다.

### 6.3 금액 구성

개념상 가견적은 창별 공급금액과 수량을 합산하고, 확인 가능한 옵션·운송·시공·현장 비용 및 세금 기준을 반영한다. 실제 산식과 각 비용의 포함 여부는 단가 자료를 확인해 별도로 확정한다.

- 총액에 들어간 항목과 빠진 항목을 결과에 표시한다. 미확정 비용은 0원으로 오해되지 않게 구분한다.
- 제품에 이미 포함된 옵션·유리 등을 다시 더하지 않는다.
- 예상 범위는 검증된 사례나 가격 규칙으로 산정한다. 일괄적인 임의 오차율을 붙이지 않는다.
- 제품·사양 표시와 실제 계산에 사용한 가격 항목이 일치해야 한다.
- 입력이나 가격표 버전이 같으면 동일 금액을 재현할 수 있어야 한다.
- 조건 수정으로 금액이 바뀌면 변경 항목과 새 결과를 표시한다.

## 7. 브랜드 및 대안 비교

LX 완성창을 중심으로 KCC 및 기타 대안을 비교한다. 비교 대상은 구체 제품·사양·제작 또는 공급 조건이 확인되어야 한다. 브랜드와 완성창·조립창 구분은 별도 항목으로 관리한다.

| 비교 항목 | 표시 원칙 |
|---|---|
| 비교 조건 | 창 수량·크기·용도, 제품과 유리 조건, 공급·시공 및 세금 범위 |
| 예상금액 | 기준일과 조건이 확인된 데이터 사용 |
| LX와 차액 | 같은 기준의 금액끼리 계산. 범위끼리 비교할 때는 대응 가능한 시나리오만 사용 |
| 사양 차이 | 완전히 같은 사양이 아니면 다른 부분을 명시 |
| 공급 가능 여부 | 대산이 실제 판매하는 상품과 비교 참고용 대안을 구분 |
| 데이터 미확보 | 해당 대안은 비교 준비 중 또는 상담 확인으로 표시 |

KCC나 기타 가격을 LX 가격에 임의 비율을 곱해 만들지 않는다. 근거 있는 환산 모델을 쓰려면 적용 범위와 검증 결과를 별도로 확정해야 한다. ‘기타’도 어떤 상품군을 의미하는지 정의한다.

## 8. LX 완성창 가치 설명

설명은 ‘고객이 중요하게 생각하는 점 → 해당 제품의 확인된 특징 → 고객에게 관련되는 이유 → 적용 조건’ 순서로 구성한다.

가격 차액과 가치 설명은 연결하되 모든 고객에게 같은 고가 제품을 일방적으로 권하지 않는다. 요구와 예산에 맞지 않거나 근거가 없으면 조건을 다시 확인한다.

설명 데이터에는 주장, 적용 제품·사양, 근거 문서와 위치, 기준일, 적용 제한, 고객용 표현을 함께 저장한다. 제작·품질 관리, 성능, 보증·사후 대응 등은 자료를 확보할 비교 주제이며, 현재 확인된 LX의 우위로 간주하지 않는다.

공개 답변에는 확인된 근거와 조건을 제시한다. 검색 실패나 자료 부재 시 일반 지식으로 제품의 성능·보증을 확정하지 않고 담당자 확인으로 넘긴다.

## 9. 결과와 상담 인계

기본 결과는 고객의 목표·관찰 사실·선택 기준·현장 확인 사항을 담은 상담 정리다. 예산을 확인한 경우 창별 목록, 비교 가능한 제품별 예상금액과 차액, 계산 가정, 포함·제외 비용과 견적 버전을 함께 담는다. 상담 정리에서 담당자 상담을 신청할 수 있다. 실측 전 결과에 ‘최종 견적’ 또는 ‘확정 견적’이라는 명칭을 사용하지 않는다.

상담 신청 시 고객이 전달할 연락 정보와 상담 내용을 확인하고 전송한다. 저장 성공 후 접수 완료를 표시하며 실패 시 재시도 방법을 안내한다. 같은 신청의 재전송으로 접수 건이 중복 생성되지 않게 한다. 신청만으로 실측 일정이 확정되었다고 표시하지 않는다.

담당자는 다음 내용을 이어받는다.

- 현장·창별 정보와 첨부 자료
- 고객이 직접 입력한 정보, 표준 가정, 미정 사항의 구분
- 고객에게 실제로 보여준 견적과 계산 조건·가격표 버전
- 고객의 관심사와 질문, 선택하거나 관심을 보인 제품
- 연락 방법과 상담 요청 내용

담당자의 구매 의사 확인과 실측 진행 여부를 기록할 수 있어야 한다. 첫 단계는 기존 상담 도구를 활용할 수 있으며 저장 위치와 담당자 업무 방식은 구현 전에 확정한다.

## 10. 필요한 데이터와 기존 자산 활용

| 데이터·자산 | 사용 목적 | 준비할 내용 |
|---|---|---|
| 제품·가격 데이터 | 지원 사양과 금액 계산 | 제품 연결, 판매금액 기준, 옵션, 비용·세금, 적용일 |
| 표준 현장 구성 | 치수가 부족한 고객의 대표 가견적 | 공간별 창 목록, 사양·수량, 적용 조건 |
| 비교 대안 자료 | LX와의 금액 및 조건 비교 | 비교 대상 정의, 가격 근거, 공급 범위 |
| 제품 설명 자료 | 질문 답변과 가치 설명 | 확인된 주장·출처·조건 |
| 기존 상담 초안 | 입력 항목과 조건별 추가 질문 | 필수·선택·담당자 확인 단계 분류 |
| 기존 챗봇 및 지식 검색 | 대화·설명·견적 표시 재사용 | 요구사항별 적합성 확인 및 수정 |
| 실제 과거 견적 사례 | 계산 검증과 범위 조정 | 같은 조건의 재현 가능한 정답 사례 |

기존 평가에 기록된 계산 경로별 가격 불일치, 제품 매핑 오류, 미매칭 기본금액, 반복 질문, 접수 중복 문제는 출시 전 검증 대상으로 둔다. 기존 기능이 있다는 이유만으로 완료 처리하지 않는다.

## 11. 기본 UI 요구

익숙한 채팅 화면, 선택 버튼, 짧은 입력, 누적되는 상담 정리, 선택적인 예산 카드로 구성한다. 수집 항목 개수나 견적 레벨 대신 고객이 이해한 선택 기준과 남은 확인 사항을 보여준다. 모바일에서 조건과 금액을 읽고 수정할 수 있어야 한다. 실제 처리 중 로딩·오류·재시도·접수 결과를 구분하며 인위적 대기는 제거한다. 내부 영업 전략, 원가·마진, 관리자 메모는 고객 결과에 노출하지 않는다.

시각 스타일의 고급화는 현 단계의 완료 조건이 아니다. 그러나 짧은 선택, 빠르고 자연스러운 반응, 선택에 따른 유용한 설명, 수정 시 달라지는 결과는 첫 버전의 핵심 경험이다. 대화 순서와 내용의 일관성 및 지루하지 않은 진행을 함께 검증한다.

## 12. 완료 판정 기준

경험 검증: 대표 고객이 자신의 상황에서 무엇을 선택·확인해야 하는지 설명할 수 있고, 대산에 상담하고 싶어진 이유 또는 이탈 이유를 확인할 수 있어야 한다. 답변이 달라지면 안내나 확인 계획이 실질적으로 달라져야 한다. 구체 시험 대상·수치 기준은 대표 시나리오를 정한 뒤 확정한다. 아래 항목은 이 경험을 지탱하는 기능 품질 기준이다.

1. 승인된 대표 시나리오에서 고객 입력부터 비교 금액 확인과 상담 접수까지 이어진다.
2. 동일 입력과 가격 버전에서 같은 금액이 나오고, 표시 사양과 계산 대상이 일치한다.
3. 창 추가·삭제·수량 수정 시 합계가 맞고, 전체 구성에 누락·중복 창이 없다.
4. 모름·지원 불가·가격 미확보에서 금액이나 제품 사실을 임의 생성하지 않는다.
5. 중간 질문 후 견적 흐름으로 복귀하고 이미 받은 답을 유지한다.
6. 비교 조건·차액·포함 비용이 일치하며 실측 전 결과임을 알아볼 수 있다.
7. 가격에 영향 없는 관심사·연락처 입력으로 금액이 바뀌지 않는다.
8. 가치 설명의 주요 주장은 적용 가능한 자료로 확인할 수 있다.
9. 접수 재시도는 중복 없이 처리되고 실패가 완료로 표시되지 않는다.
10. 담당자가 고객에게 제시된 결과와 미정 사항을 확인해 상담을 이어갈 수 있다.

운영 지표는 목적별 유용한 안내 도달, 상담 정리 확인, 상담 신청, 유효 상담, 실제 실측과 이탈 이유다. 가견적 완료는 선택 경로의 지표이며 단독 성공 기준으로 삼지 않는다. 가견적·정식 견적의 차이는 사양 변경과 계산 오류를 구분해 분석한다. 허용 차이와 목표 전환율은 실견적 자료 검토 및 초기 운영 후 정한다.

## 13. 다음 상세화 순서

우선 대산의 실제 상담에서 고객이 전문성을 느끼거나 선택을 바꾼 사례 하나를 확보하고, 이를 짧은 대화 시나리오로 구성한다. 그 시나리오에서 필요한 내용과 기능을 아래 순서로 구체화한다. 기존 입력·가격 오류 수정은 기본 품질 작업으로 병행한다.

1. 지원할 대표 고객·현장·창 구성과 공급·시공 범위를 정한다.
2. 실제 자료로 비교 가격 기준과 LX 완성창의 설명 근거를 확정한다.
3. 입력 항목별 질문·선택지·미정 처리·조건별 분기를 작성한다.
4. 가견적 산식, 표준 구성, 비교 결과 항목을 확정한다.
5. 상담 접수와 담당자 인계 항목·처리 채널을 확정한다.
6. 기존 구현과 대조해 재사용·수정 범위를 정하고 대표 사례로 검증한다.

먼저 확정할 질문은 ‘누가 직접 이용하는가’, ‘무엇의 가격을 비교하는가’, ‘어떤 장점을 근거로 설명하는가’다. 답변 전에도 이 구조를 기준으로 문서를 구체화할 수 있으나, 미정 사업 조건을 자동으로 확정하거나 출시 데이터로 사용하지 않는다.
